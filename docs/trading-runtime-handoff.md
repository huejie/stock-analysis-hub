## Hermes 的操作约定

1. 明确股池的唯一维护者。若 Hermes 定时维护股池，先保持 `TRADING_SCHEDULE_ENABLED=false`，避免内置自动热榜同步覆盖其预期股池；Scheduler 进程仍需运行以消费手工数据任务。
2. 导入股池后记录版本 ID、日期、股票数量；触发行情任务后记录 job ID，并轮询到明确成功或失败。点击成功、HTTP 202、QUEUED、RUNNING 都不等于行情更新完成。
3. 生成计划前检查信号日的数据健康、账户、持仓与策略版本。BLOCKED 必须处理缺失原因；不要通过反复强制生成规避门禁。
4. 生成计划后记录 run ID、账户、信号日和目标交易日。只有 READY/PARTIAL 才进入人工检查；进行中、失败和已替代均不当作可执行计划。
5. 人工决定是否发布以及是否在券商执行。Hermes 不自动激活策略、不自动发布或下单。成交按真实成交结果录入，重试保留同一个 `client_execution_id` 和相同载荷。
6. 每轮记录股池版本、任务 ID、计划 ID、最终状态与错误原因。若需修复后强制重建，应记录原因并保留旧计划供追溯。
